# GraphDigger

从科研图表图像中提取曲线坐标数据的 macOS 应用(GetData Graph Digitizer 的复刻实现)。

> `GraphDigger` 是**临时工程代号**,正式产品名待定且需查商标(原版 "GetData" 不建议沿用)。

## 当前状态

**完整流程已可用**:打开图片 → 标定坐标系 → 取曲线颜色 → 取点 → 导出。算法层与界面层都已实现并验证。

- 通用二进制:**arm64 + x86_64**,Intel 与 Apple 芯片都能跑
- 体积:`.app` **2.8 MB**,`.dmg` **1.4 MB**
- 单测:**175/175 通过**;内置自检:**120/120 通过**(含 PNG 真实解码路径、刻度与方向校验)
- **整个工程可以存成一个文件**(`.gdproj`):图片、标定坐标系、曲线与点位都在里面,发给别人,对方装了本应用双击就能看到完整工程

## 快速上手

```bash
./scripts/build_universal.sh          # 构建
open dist/GraphDigger.app             # 运行

# 生成一张带已知真值的示例图,照着下面的数值标定即可验证整条链路
dist/GraphDigger.app/Contents/MacOS/GraphDigger --make-sample samples/sample.png
```

示例图会打印出四个参考点的像素坐标与对应数值,以及曲线颜色,照着点即可。

> 仓库里已经放了一张:`samples/sample_logistic.png`(900×640,logistic 曲线)。
> 参考点:`X min 像素(80,580)→0`、`X max 像素(860,580)→10`、
> `Y min 像素(80,580)→0`、`Y max 像素(80,40)→5`;曲线颜色 RGB(210,40,40)。

## 操作流程

主界面顶部是**工具栏**,日常操作用按钮即可,不必翻菜单。工具栏按流程顺序排布,并高亮当前所处步骤:

```
[↺|↷] │ [浏览] [标定] [取色] │ [区域取点] [自动跟踪] [手工取点] │ [橡皮擦] [重新选点] │ [复制] [导出…] [适配]
第 N 步:……                                          曲线 2 条 · 数据点 340
⚠️ 未标定 · 缩放 389% · 背景 RGB(254,254,254)              间距 8px  [———●———]
```

工具栏下方一行会**随状态提示当前该做哪一步**,例如"第 2 步:点「标定」建立坐标系";取点后变成"数据已就绪 —— 可点「复制」或「导出…」"。

首尾两组之间的竖线是真实存在的分隔条,把**取点**(区域取点/自动跟踪/手工取点)和**修点**(橡皮擦/重新选点)分开;点编辑也在修点这一组里,只是工具栏已经没宽度了(见下);最左端的 ↺|↷ 不属于任何一组,它们作用于"上一步做了什么",与当前拿的是哪个工具无关。

### 状态条右端的参数控件

状态条右端是**当前工具自己的那个数**,只在该工具有这个数时出现,直接拖滑槽即可改:

| 工具 | 控件 | 含义 |
|---|---|---|
| 橡皮擦 / 点重排 | `半径 18` | 圆圈半径(视点),圈碰到的点被删 / 被重新编号 |
| **区域取点 / 重新选点** | `间距 8px` | **网格间距**——相邻扫描线相隔多少像素,越小点越密 |
| **自动跟踪** | `间距 3px` | **取点密度**——沿曲线每隔多少像素留一个点,越小越密 |
| 浏览 / 标定 / 取色 / 手工取点 | (不出现) | 这几个工具没有可调的数,把整行还给状态文字 |

**为什么放在这儿**:网格间距原先只在 `操作 ▸ 网格间距…` 的弹窗里,取点前看不见;自动跟踪的密度则根本没有入口——跟踪沿曲线每个像素都取一个点。这两个数决定"这条曲线取多少点",是工具的一部分而不是偏好设置,所以放在选中工具时视线本来就会落到的位置。

**拖动即时生效**:下一个框选/跟踪就按新值走,不需要重新取色或重新标定。菜单里仍保留 `操作 ▸ 网格间距… / 取点密度…` 可以键入精确值,范围与滑槽完全一致(1–40)。

### 网格方向:同一个 x 有多个 y 的曲线

`区域取点` / `重新选点` 的网格**可以换轴**。这不是密度旋钮,它决定**哪些点根本取得到**。

```
操作 ▸ 网格方向 ▸ X 网格   ← 默认。扫描线竖直、从左到右,一列一个点
                   Y 网格     扫描线水平、从上到下,一行一个点
```

| 曲线形状 | 该用哪个 |
|---|---|
| 单值函数 `y = f(x)`(绝大多数折线图、曲线图) | **X 网格** |
| 在 x 上单调、因而 `x = f(y)` 唯一:竖着的波浪线、竖直鼓包 | **Y 网格** |
| 在**两个轴上都多值**:闭合回环、滞回环、心形线 | 都不行,**用点重排** |

**为什么这不是可选项。** X 网格按列采样,而「这一列上曲线在哪」对多值曲线有多个答案。它不是精度差——点都在曲线上、一个不少——而是**顺序错**:它按列访问各个交点,于是序列在两条分支之间来回跳。画出来是一条打结的折线,导出的数据也没法直接用。

同一张图换成 Y 网格,每个扫描行只与曲线相交一次,顺序自然是对的。实测一条 `x = 40 + 18·sin(y/12)` 的竖直波浪线:X 网格的折线总长是 Y 网格的 **2 倍以上**(来回跳),而 Y 网格每行一个点、严格按行递增。

> ⚠️ **换轴只对"在 x 上单调"的曲线有效,对回环无效。** 实测一个半径 150 的圆环、间距 10:
> X 网格与 Y 网格的输出**完全相同**(都是 60 点、折线长 14047px,而真实周长只有 942px —— **14.9 倍**)。
> 原因很直接:圆环每一**行**、每一**列**都与曲线交于两点,换轴只是把同一个困境转了个方向。
> 回环类曲线只能靠**点重排**(圈刷)定序 —— 这不是"另一个办法",是唯一的办法。
>
> 上面那张对比图(`网格方向-对比.png`)之所以成立,是因为那条曲线**在 x 上单调**:每行只有一个交点。

### 网格偏移:让扫描线穿过指定的一列

```
操作 ▸ 网格对齐到坐标轴起点    ← 让一条扫描线正好落在 X 轴起点那一列
操作 ▸ 网格偏移…               ← 直接填像素相位(0 到 间距-1)
```

**为什么要它**:扫描线落在哪里是有系统偏差的。间距 8px 的网格如果整体错开 4px,整批采样点就整体偏 4px;而论文图上的刻度线、数据符号都有固定位置,网格与它们对上时读数最准。对齐到坐标轴起点之后,采样点就落在「整数值」上,后续处理省事。

**网格锚定在图像上,不是锚定在选框上。** 所以重画选框只会把网格**裁短**,不会把它挪走——对齐一次就够了。这条性质有单测钉着(两个起点相差非整数倍间距的选框,窄的那个的列必须是宽的那个的子集)。

状态条上会显示当前用的是什么网格,例如 `X 网格 · 间距 8px · 偏移 6px`——换轴时画面本身不会变,没有这句话就分不清是换了模式还是菜单点空了。

### 逐个点地修:点编辑 与 可编辑的数据表

`区域取点` 与 `自动跟踪` 是按**批**取点的,`橡皮擦` 与 `重新选点` 是按**圈/框**修的。
剩下最后一类:采样本身没问题,只差某一个点偏了几个像素——这时需要的是**只动那一个点**
的手段。两个入口:

| | 做什么 | 快捷键 |
|---|---|---|
| **点编辑**(画布上) | 光标下的标记可**拖动**;**点在两点之间的连线上**则插入一个新点;**`⌫`** 删除选中的点 | `⇧⌘E` |
| **数据表**(右侧面板) | X / Y 单元格双击可**直接键入数值**,`⌫` 删除选中的那一行 | — |

`⇧⌘E` 与橡皮擦的 `⌘E` 是成对的:同一件事的两种粒度,字母相同、修饰键说明是哪一种。
点编辑也是这批修复工具里**唯一能加点**的——橡皮擦和重新选点都只能减。

**插在哪一段,决定折线怎么走。** 新点不是"追加到末尾",而是插进那两个标记在**当前显示
顺序**里的位置;在「反转顺序」或「重排顺序」的曲线上,这两个邻居在存储数组里可能是从后
往前的,按"插在左边那个之后"会把新点放到折线的另一头。这条规则在 `GDCore` 里
(`storedInsertionIndex`),四种顺序都有单测。

> **为什么是「最近特征胜出」而不是「够近就抓标记,否则连线」。** 默认网格间距 8px 时,
> 标记彼此只隔 8px,而标记的命中半径是 10pt——它会盖住整条连线,于是**在区域取点出来的
> 曲线上插入点根本按不出来**,而那正是这个工具存在的理由。所以改成一件事:
> 标记距离和线段距离谁近听谁的。悬停时画的小圈就是这个判定的输出,画面承诺什么、
> 点击就做什么。

**改的是哪一轴,就只换算哪一轴。** 表格里的数是图表值,写回时要过标定换成像素;这里
只换算被改的那个轴。整体过一遍标定会在最后一两位浮点上挪动另一个坐标,而"改了 X 却
悄悄动了 Y"这种缺陷没有任何症状。没有标定时表格显示的就是像素,直接改像素。

**输入不认逗号。** `1,000` 里的逗号当千分位和当小数点的概率差不多,按 `1.000` 读会差
一千倍而屏幕上没有任何提示。解析不了的值会被拒绝、原值放回单元格——一个看得见的结果。

### 两个"用来看"的视图

取完点最要紧的一步是**检查对不对**,而画布上最难看出的恰恰是这件事——标记点就压在曲线的同一条线上,歪半个像素根本看不出来。所以有两个视图专门干这个:

| | 做什么 | 快捷键 |
|---|---|---|
| **隐藏原图** | 把扫描图藏起来,只留取到的点。**位图并没有被丢掉**——掩膜、命中检测、取色全都照常工作,它只是不画出来 | `⇧⌘I` |
| **数据视图** | 独立窗口,把点按**数据坐标**画出来。对数轴也按对数摆 | `⇧⌘D` |

**为什么数据视图要单独一个窗口**:工具栏只剩 13pt、侧栏 272pt 对 1440pt 的屏,放不下一个"要读"的图;而它真正的用处是放在画布旁边对照着看。

上面那张图(`数据视图-取歪看得出来.png`)就是它的价值:同一条竖直波浪线、同一批点,按列扫出来的顺序在数据坐标里是一串**竖直跳变**,按行扫的没有。那个跳变在原始图上完全看不见。

### 撤销 / 恢复

工具栏**最左端**是一对:↺ 退回上一步(`⌘Z`),↷ 把退回的那一步找回来(重做,`⇧⌘Z`)。一次 `⌘Z` 按多了就退过头,这是最常见的误操作,所以两个方向放在同一个位置的两半。Edit 菜单会把这一步的名字写出来——「撤销 擦除」「撤销 区域取点」——所以不必先猜它要退到哪里。

**为什么两半挤在一个控件里。** 工具栏宽度是硬的:面板占 272pt,最窄一块屏幕 1440pt,留给工具栏 1168pt。两个独立的图标按钮要 39 + 39 再加间距 = 81pt,塞不进去;同样两个符号接成一个分段控件只要 49pt——撤销和恢复本来就是一件事的两半,画成一体的那个控件恰好也是装得下的那个。两半**各自**置灰:撤一次之后有东西可恢复、可能已经没有东西可撤销,所以不能共用一个开关。

**一次手势就是一步。** 橡皮擦拖过一整条曲线擦了 58 个点、点重排扫过半张图,都只记一步;撤销一次整笔回来,而不是一个像素一个像素地退。这是它唯一需要设计的取舍:橡皮擦在每个 `mouseDragged` 上都改模型,按事件记历史会留下一打条目。

**可以撤销的**:标定 / 改标定数值 / 清除标定、取曲线颜色与背景色、区域取点 / 自动跟踪 / 手工取点、橡皮擦、重新选点、移动点 / 插入点 / 删除点、改单元格里的坐标、点重排、清除重排、新增 / 删除 / 重命名曲线、清除某条曲线的点、切换取点顺序、显示隐藏、颜色容差、拖动标定标记。

**不进历史的**:切换工具、在右侧面板选中曲线、缩放平移、圈半径与两个取点间距。前三个不是对数据的改动——"选中哪条曲线"只是下一个动作作用在谁身上;后三个是**当前设置**而不是**已经做过的事**,尤其滑槽拖动一秒里会改几十次,进了历史就会把真正的操作淹掉。

**实现上是整份状态快照,不是逆操作。** `ProjectState` 就是几个数组,一份快照几百 KB,栈上限 30 步。给二十多个 mutation 各写一个逆操作,写错一个就会悄悄产出一个用户从未有过的状态——而快照没有这个失败模式。两处配套:撤销后**掩膜按需重建**(只重建颜色真的变了的那几条曲线,没动的沿用缓存),**换图时清空历史**(旧图的像素坐标在新图上没有意义)。

> 这也让「点重排」的设计多了一层保障:扫错了既可以 `清除重排` 回到取点顺序,也可以直接 `⌘Z`。

| 步骤 | 工具栏按钮 | 菜单 | 快捷键 |
|---|---|---|---|
| **撤销上一步** | ↺ | Edit ▸ 撤销 xxx | `⌘Z` |

### 导出

`File ▸ Export Data` 导出**全部曲线**;`File ▸ Export Current Curve` 只导出**当前选中的那一条**(文件名也取曲线名)。剪贴板同理:`⌘C` 复制全部、`⌥⌘C` 只复制当前。

**多条曲线时的排布**:CSV / TSV 给的是**一张宽表**(表头 `x1,y1,x2,y2,…`,每行对得上),因为 `# 名称` 注释行不是 CSV 的一部分——pandas 会报错、Excel 会把名字当成一行数据,两种都错得没声音。TXT 给的是**带名字的数据块**,因为它是给人读的,宽表反而不如分块清楚。

`File ▸ Export Data` 有七种格式。**XLSX 是真正的 Excel 工作簿**,每条曲线一个工作表,`x` / `y` 两列、数值是真数字(不是文本,所以能直接求和、排序、画图)。

它是自己写的:一个 `.xlsx` 就是一堆 XML 打进一个 ZIP,所以 `GDCore` 里有一个**最小 ZIP 写入器**(stored、不压缩)和一个 OOXML 生成器,没有引任何第三方库,也没有 shell 出去调 `/usr/bin/zip`。不压缩是因为 Foundation 没有 deflate,而为了几 KB 的 XML 手写一个 deflate、再赔上一堆"某个读取器打不开"的可能,不划算——`stored` 是格式本身的一部分,不是它的近似。

产物用独立的读取器验过:每个条目的 CRC 正确、六个部件齐全、表名按 Excel 的规则清洗(`压力/MPa [支]` → `压力_MPa _支_`)、数值读回来是数字、与标定换算逐位一致。

其余格式:CSV / TSV / TXT / XML / DXF(AutoCAD)/ EPS(PostScript)。

**未标定或未取色时,状态栏会显示 ⚠️ 提示**——导出前必须先标定,否则数据无法换算成实际数值。

## 项目文件(`.gdproj`)

> **打开图片 与 打开项目 不是一回事。** 打开一张**图片**是开始一份新工作:上一张图的曲线和
> **标定坐标系一起清掉**(四个锚点是那张图的像素位置,留在新图上只会让坐标看着对、其实是错的)。
> 打开一个**项目**则把图片、标定、曲线、点位整份恢复。两条路径都会先问一句"要不要保存"。


`⌘S` 把整个工程写进**一个文件**:原始图片、标定坐标系(含四个锚点的像素位置)、每条曲线的名称/颜色/容差/取点顺序/重排记录/显示开关,以及已取的全部点位。`⌘O` 打开它,回到存盘那一刻的样子。

发给别人时不需要附带图片——图片在文件里。对方装了这个应用,双击 `.gdproj` 就能看到完整工程,不需要配任何东西。

**怎么知道有没有没存的改动**:窗口标题栏的关闭按钮上会出现一个小圆点,状态条上也会多一句「未保存」。关窗口或退出时如果有未保存的改动会先问一句。这个标记是**和文件比对**出来的,不是"动过就打勾"——所以 `⌘Z` 退回存盘时的状态后,标记会自己消失,不会为一段已经撤销掉的改动来问你。

### 文件长什么样

单文件容器,图片原样存放,结构化数据可以不解码图片就读出来:

```
偏移      长度     内容
--------  -------  --------------------------------------------------
       0        8  魔数 — "GDIGPRJ" 加一个 NUL
       8        4  格式版本,小端 uint32
      12        4  头部长度,小端 uint32
      16        N  头部 — UTF-8 的 JSON,`ProjectHeader`
   16 + N   到文件尾  图片 — 打开时那份文件原本的字节,一字未改
```

十六个字节的序言、两次整数读取,没有第三方依赖,也不会被压缩器弄坏:

- **不用 zip**:Foundation 没有 zip API,要么引依赖,要么 shell 出去调 `/usr/bin/zip`——那是一个进程启动加一条无法单测的错误路径。
- **不用 base64 套 JSON**:图片占文件体积的绝大部分,base64 白白胀三分之一,还得在进出两头各做一次编解码。
- **图片存原始字节,不重新编码**:每个数据点都是**这份图片**的像素坐标。PNG 解出来再编回去不保证逐位相同,差一个比特就会让标定锚点和所有曲线对着一张已经不存在的图。原样存放还让往返可以**证伪**——自检比对的是字节,不是"看起来差不多"。

头部是明文 JSON,`xxd` 就能看:

```json
{"savedAt":"2026-10-03T09:09:28Z","state":{"calibration":{"x":{"valueMin":100,"valueMax":700,
 "isLogarithmic":false,"pixelMin":44,"pixelMax":572},"y":{"valueMin":0.5,"valueMax":25,
 "isLogarithmic":true,"pixelMin":512,"pixelMax":36}},"gridSpacing":13,…},
 "appVersion":"0.1.0","image":{"fileName":"示例图表.png","pixelWidth":900,"pixelHeight":640}}
```

### 兼容性

版本号放在序言里而不是头部里,这样读不了的未来格式在**任何解析之前**就被拒绝,新格式可以随意改动头部的形状。旧版应用打开新版文件会明确说「这是更新版本保存的,请升级」,而不是读一半。

反向——新版读旧版文件——靠一条规则:**`ProjectState` 之后再加字段,必须写成 Optional。** 合成出来的解码器对 Optional 属性用 `decodeIfPresent`,键不在就是 `nil`,旧文件照样读得进来。

### 失败时会说什么

坏文件不会被当成空工程打开。几种情况分别给不同的话,因为它们要的应对完全相反:

| 文件 | 提示 |
|---|---|
| 根本不是工程(比如一张普通 PNG) | 这不是一个 GraphDigger 项目文件 |
| 头部长度报得比文件还大 | 文件不完整,可能被截断 |
| 版本比当前应用新 | 是更新版本保存的,请升级应用 |
| 头部解析不了 | 内部描述数据已损坏 |
| 容器完好但没有图片数据 | 文件里没有图片,无法还原 |
| 容器完好、图片字节是坏的 | 图片解不开,文件可能损坏 |

最后一条单独列出来,是因为它**最像成功**:容器的头部完全正常,只有图片解不开。`NSImage` 是惰性解码的,拿一段截断的 PNG 也会给你一个对象,直到有人真的去取像素才失败——所以画布在装载时会先把位图解出来,解不出来就整个拒绝,而不是打开一个"有曲线数据、没有图"的窗口。

## 关于标定(坐标系)

标定做的事是:把图像上的**像素位置**和图上坐标轴的**实际数值**对应起来。它是后续一切换算的前提——没标定就没法把"第 523 行"变成"2.5"。

### 四个标记的取法

点「标定」(或 `⌥⌘S`)后,依次在图上点四下,每点一下都会出现带标签的标记,状态栏同时提示下一个该点哪里:

| 顺序 | 位置 | 标记 |
|---|---|---|
| 1 | **X 轴起始**(横轴上某个已知值的位置) | ① 蓝色圆点 |
| 2 | **X 轴末端**(横轴上另一个已知值的位置) | ② 蓝色圆点 |
| 3 | **Y 轴起始**(纵轴上某个已知值的位置) | ③ 青色圆点 |
| 4 | **Y 轴末端**(纵轴上另一个已知值的位置) | ④ 青色圆点 |

点完第 4 个弹出面板,逐行填这四个标记对应的数值;某一轴是对数刻度就勾上那一行的 log。

**为什么是四个点,不是三个**:两个轴**不需要共用同一个原点**。很多图是"X 轴沿底部、Y 轴沿左侧"两条线,彼此并不相交——三点方案会把同一个角点硬塞给两个轴,这类图会被悄悄标错。多花一次点击,换来的是两条轴各自独立。

**"起始/末端"不必真的是轴的最远端**——只要是你知道确切数值的任意位置即可,比如起始取在 0、末端取在刻度 10 处。数值的大小顺序也不重要,反向标定同样成立。

### 方向怎么定

由**你点击的像素位置**决定,与填写顺序无关。X 轴只取两个 X 标记的**列坐标**,Y 轴只取两个 Y 标记的**行坐标**——所以:

- 从右往左画的 X 轴、从下往上画的 Y 轴都能正确映射(有测试覆盖)。
- 点得稍微偏离轴线也没关系,另一个方向的偏移会被自动忽略。
- **Y 轴数值最小在下方**这种反向情况天然成立,不需要勾"反转"。

### 怎么核对标定对不对

标定完,图上会画出:

- **蓝色虚线**(X 起始→X 末端)、**青色虚线**(Y 起始→Y 末端)——就是你刚才描的那两条轴。
- **两条线上按标定值画出刻度并标注数字**。

**刻度落在图上坐标轴自己的格线/数字上,就说明标定正确**;对不上就是某个标记点错或数值填错。这是肉眼判断标定正误的可靠方式——只看一串数字是看不出来的。

> 四个标记本身**平时不画**:它们是用来拖的,不是用来看的,标定完成后留在图上会正好压在曲线上。把鼠标移到某个标记附近,四个标记连同数值标签(形如「① 0」)会一起重新出现,移开又消失。标签只写序号和该标记对应的数值,不显示像素坐标——像素坐标在标定完成后没有任何意义。

### 微调与重来

- **拖动标记**:在「浏览」模式下把鼠标移到标记附近让它显形,然后直接拖。每个标记只移动自己那个轴的一端,不会把另一个轴带偏(轴上没有"公共原点"这个由两个轴共享的东西);刻度和虚线实时重画。
- **菜单 Operations ▸ Edit Calibration Values…**:只改数值,**四个标记的位置不动**——改错的是数字,不是描的位置。
- **`⌥⌘R` 清除标定并重来**:清掉标定重新点。**已提取的数据点不会丢**——它们存的是像素坐标,重新标定后会自动按新坐标系换算。这也是把点存成像素而非数值的原因。

## 关于系统版本兼容

实测 Xcode 27 / Swift 6.4 工具链的硬约束(**这些数字是量出来的,不是猜的**):

| 途径 | 能达到的最低部署目标 |
|---|---|
| Swift Package Manager `platforms:` | **macOS 12.0** —— 写 `.v10_15` 或 `.v11` 会被静默抬升到 12.0 |
| 裸 `swiftc -target` | **macOS 11.0** —— 连 `-target macosx10.13` 编出来 minos 也是 11.0 |
| `MACOSX_DEPLOYMENT_TARGET` 环境变量 | 被 SPM 忽略,无效 |

**结论:本工具链下 macOS 11 是绝对下限,10.x 做不到。** 要覆盖更老系统得换旧版 Xcode。

- **默认构建 = minos 12.0**(Monterey,覆盖 2015 年起的 Mac),来自 `Package.swift` 的 `.v12`,干净无警告。
- **`--min-os 11.0` = minos 11.0**(Big Sur,覆盖 2013 年起的 Mac)。该路径**逐架构构建后用 `lipo` 合并**——因为全局 `-Xswiftc -target` 会覆盖 SPM 的按架构 target,把两个切片都编成同一架构导致合并失败。

两条路径产出的都是真正的通用二进制,已用 `lipo -info` 与 `vtool -show-build` 逐架构核验。

## 设计要点

- **数据点存像素坐标,不存数值。** 导出时才经 `CalibrationMap` 换算成实际数值。好处是重新标定(改参考值、切换 log)会**自动更新所有已提取的曲线**,不会留下算错的旧数字。
- **`GDCore` 不依赖 AppKit。** 算法、模型、导出都在里面,可脱离界面单测;界面只负责事件转换与绘制。
- **掩膜有三道闸门:距离 → 背景 → 色相。** 前两道分得开"曲线 vs 背景",分不开"这条曲线 vs 那条曲线"。加权 RGB 距离会**压缩色差**:权向量 `(2,4,3)` 被自身长度归一掉,顺着它的差(灰阶变化)按原尺寸报,横着它的差最多报小 2.4×——默认容差 60 实际放进来的普通 RGB 距离上限约 145。报告里那张图,绿色 `(103,186,103)` 与橙色 `(255,164,84)` 在这个度量下只差 **59.7**,是肉眼可辨却过不了闸门的差;而橙色到白纸是 115.9,即它**离绿曲线比离背景还近**,两道旧闸门都说"是"。
  真正不同的是色相,而色相恰好是抗锯齿唯一不动的东西:描边像素是 `t·墨 + (1-t)·背景`,背景中性时这个混合只把颜色往灰里拉、**不改方向**。所以同一条曲线从芯到最淡的边缘色相方向完全一致,另一条曲线则不然。实测:绿掩膜里剔掉 17 668 个橙色像素与 19 376 个蓝色像素,55 597 个绿色像素一个不少。
  另一条附带规则是**中灰不是彩色线的墨**:中灰在同一个度量下确实"离绿比离白近",坐标轴的抗锯齿灰边会被吞进来,而它色度为 0,判得出来。色度低于门槛的**曲线**则让闸门整体失效(浅色曲线走这条路),所以浅色曲线行为不变。`ForegroundMask.build(hueTolerance:)` 传 180 即关掉这道闸门。
- **精度目标 ≤0.5% 满量程**,实测 p95 ≈ 0.17%(5 种曲线族 × 3 档采样密度)。

## 已知限制

- **45° X 交叉漏检**:两条长直对角线交叉时线跟踪不会停下,会沿主线走完。属保守失效(只漏报不误报)。修法已记录在 Phase 0 报告。
- **自动跟踪在急弯的外侧会停**:游走是逐像素的贪心走法,当弯道的曲率半径小于线宽时,它会沿着带子的外沿走到切点,然后停在那里(实测一条竖直波浪线,若干起点停在 y≈8 / y≈21 处,走了 15–19 步)。**这不是取不到点,是取到半条线后正常结束**——从另一端再点一次即可。竖直段、回环与急弯仍以「区域取点 + Y 网格」或「点重排」更稳。
- **平行双线间距 < 3px** 会粘连成一条,是分辨率物理极限;可放大后用手工取点绕开。
- **虚线间隔 > 4px** 时自动跟踪会断;自动跟踪的桥接半径目前写死为 4px,尚未做成可调项。
- **Y 网格只对"在 x 上单调"的曲线有效,对回环无效**:实测半径 150 的圆环,两种网格输出**完全相同**(折线长都是真实周长的 14.9 倍)。闭合环 / 滞回环只能靠「点重排」定序。
- **网格只有两个正交方向,不能旋转**:倾斜扫描件上拍歪的坐标轴还处理不了(FR-2.5 旋转标定、FR-5.6 网格旋转都未做)。
- **未做自动保存与崩溃恢复**:只有显式 `⌘S` 会落盘。
- **未做 Developer ID 签名与公证**,仅 ad-hoc 签名,适合本机运行;对外分发需要 Apple 开发者证书。
